Imagens responsivas,
tipografia fluida
e container queries

A janela não é a única medida. Uma imagem precisa de uma fonte adequada, um título deve crescer sem bloquear a leitura e um componente deve responder ao espaço que recebe. Hoje fechamos a fase sem framework do projeto integrador.

Aplicar max-inline-size: 100% numa imagem de vários megabytes resolve o quê?

  • Reduz necessariamente o tamanho do download
  • Limita a caixa visual, mas não comprime o arquivo baixado
  • Gera automaticamente versões menores do arquivo

1. Separe caixa visual, recurso e significado

CSS evita que a imagem ultrapasse a caixa disponível. O HTML oferece candidatos de recurso. Texto alternativo comunica o significado quando a imagem não é percebida. Nenhuma dessas responsabilidades substitui as outras.

img { display: block; max-inline-size: 100%; block-size: auto; }
/* No HTML: width e height descrevem as dimensões/proporção intrínsecas. */

Os atributos width e height permitem reservar a proporção antes do carregamento. CSS fluido pode mudar o tamanho renderizado mantendo essa proporção. object-fit: cover pode recortar quando a caixa impõe outra proporção; não significa “mostrar a imagem inteira”.

Use alt conforme o contexto. Imagem informativa recebe descrição útil; puramente decorativa recebe alt="". Uma legenda não torna o atributo automaticamente dispensável.

2. srcset oferece candidatos; sizes descreve o slot

Com descritores w, cada número informa a largura intrínseca real do arquivo. sizes estima a largura que a imagem ocupará no layout, em pixels CSS. As condições são avaliadas em ordem: a primeira correspondente fornece o tamanho; o último valor funciona como fallback.

<img src="paisagem-960.jpg"
     srcset="paisagem-480.jpg 480w, paisagem-960.jpg 960w, paisagem-1440.jpg 1440w"
     sizes="(min-width: 48rem) 48rem, 100vw"
     width="960" height="640" alt="Descrição contextual">

Neste exemplo, o CSS deve realmente limitar o slot a 48rem e usar a janela inteira abaixo disso. sizes não aplica esse layout: ele precisa concordar com o CSS.

O navegador escolhe considerando o slot, a densidade da tela e suas políticas de carregamento/cache. Não há promessa de baixar sempre o menor arquivo nem de trocar por um menor ao encolher a janela. Inspecione currentSrc, a rede e a caixa renderizada; para comparar downloads, faça uma nova carga com cache desativado.

Para uma imagem de tamanho CSS fixo, candidatos 1x e 2x representam densidades. Não misture descritores w e x no mesmo conjunto. sizes se relaciona ao conjunto com descritores w.

4. picture: direção de arte e formatos

Quando o enquadramento deve mudar, use picture. Cada source pode oferecer um conjunto condicionado por media ou type. O img final é obrigatório: contém o texto alternativo e o fallback. Não coloque alt em source.

O recorte estreito acima tem proporção diferente: as dimensões no source descrevem esse recurso. Os SVGs locais são esquemas didáticos leves, utilizáveis offline; não demonstram ganho de compressão de uma fotografia. No projeto, exporte e meça versões raster reais quando o conteúdo for fotográfico.

Para formatos, uma sequência comum é source type="image/avif", depois WebP e, no img, um fallback adequado. Arquivos e MIME devem corresponder. Use loading="lazy" para imagens fora da área inicial quando apropriado; não adie automaticamente a imagem principal que precisa aparecer de imediato.

5. Tipografia fluida com limites e leitura

clamp(mínimo, preferido, máximo) limita um valor fluido. Aqui o título combina uma parcela relativa à raiz com outra relativa ao viewport:

h1 { font-size: 2rem; /* fallback */
     font-size: clamp(2rem, 1.5rem + 2vw, 3.5rem); }
p { max-inline-size: 65ch; line-height: 1.6; }

ch se baseia na medida de avanço do glifo “0”, não numa contagem exata de letras. line-height sem unidade escala com a fonte do elemento. Evite alturas rígidas e recortes que impeçam o texto ampliado de caber.

Usar rem junto de vw ajuda a considerar a preferência de fonte, mas não certifica acessibilidade. Teste aumento de texto até 200%, zoom e refluxo sem perda de conteúdo/funcionalidade; valores baseados em viewport podem compensar parte do crescimento sob zoom. Se necessário, ajuste a fórmula ou use tamanhos relativos sem a parcela de viewport.

Substitua o título de 8vw por clamp com mínimo 2rem, preferido 1.5rem + 2vw e máximo 3.5rem, mantendo fallback de 2rem. Remova a altura rígida e o recorte do artigo. Limite o parágrafo a 65ch e use entrelinha 1.6 sem unidade.

Teste o título nos extremos da janela e o parágrafo com texto extra. Que regra esconde o conteúdo em vez de permitir que a caixa cresça? Observe se os limites da fonte e a entrelinha acompanham o tamanho do texto.

6. A query pertence ao espaço do componente

Media query observa o ambiente; size container query observa o tamanho de um ancestral elegível. Declare um wrapper com container-type: inline-size. Em escrita horizontal, inline-size corresponde à largura. Um nome permite escolher o contexto desejado quando existem containers aninhados.

.slot { container: ficha / inline-size; }
.ficha { display: grid; gap: 1rem; }
@container ficha (min-width: 30rem) {
  .ficha { grid-template-columns: 1fr 2fr; }
}

A query de tamanho não permite ao container consultar o próprio tamanho para estilizar a si mesmo: o elemento estilizado procura um ancestral elegível. Separe .slot e .ficha. Contenção de tamanho afeta dimensionamento; evite container-type: size sem entender também a dimensão de bloco.

1cqi equivale a 1% do inline-size do container elegível para esse eixo. Sem container elegível, a unidade usa a unidade de viewport pequeno correspondente, não zero. Não confunda esse fallback com a condição @container funcionando.

Use base legível fora da query. A melhoria pode ficar em @supports (container-type: inline-size). Uma media query baseada na janela não é equivalente automática a uma query do componente.

A mesma ficha está na lateral e no conteúdo principal. O que deve orientar seu arranjo interno?

  • A marca do aparelho
  • Uma largura fixa global para todas as fichas
  • O tamanho de um ancestral elegível de cada ficha

7. Auditoria: técnica moderna não é prova de correção

A ficha deve caber no wrapper, mostrar todo o texto com fonte ampliada e ganhar duas colunas quando seu wrapper alcançar 30rem. Não há outro container ancestral. Investigue as afirmações e marque somente problemas reais.

Compare separadamente imagem, texto e contexto de consulta. Procure evidências: a regra limita a caixa ou a deixa transbordar? O ancestral tem o tipo de contenção necessário? O texto permanece completo? Uma unidade moderna, por si só, não garante nem invalida o resultado.

  1. A largura rígida da foto pode ultrapassar o wrapper.
  2. A altura automática da foto deveria ser substituída por um valor fixo.
  3. Nomear o wrapper, sem tipar a contenção, não basta para a size query.
  4. A query deveria estilizar o próprio wrapper em vez da ficha descendente.
  5. O título apenas em vw exige revisão para leitura com fonte ampliada.
  6. line-height sem unidade é inválido.
  7. Altura rígida com recorte ameaça a integridade do conteúdo.
  8. Limitar o parágrafo em ch é um erro por não usar pixels.

8. Exercício: viewport organiza a página; container organiza o componente

Mantenha a media query de 55rem: ela organiza a página em lateral e conteúdo de acordo com o viewport. Remova somente a media query de 30rem, que torna todas as fichas horizontais por causa da janela. Crie em cada slot um container nomeado ficha de inline-size. Preserve a base de uma coluna e use duas colunas 1fr 2fr apenas quando o container atingir 30rem. Sem alterar o viewport de 1000px, demonstre a ficha estreita empilhada e a larga em duas colunas. Aplique ao h3 o fallback 1.25rem e clamp(1.25rem, 1rem + 1cqi, 2rem).

Separe as perguntas. A mudança é da composição da página inteira ou do arranjo interno de um componente reutilizável? Compare as duas fichas sem mudar a janela e identifique qual ancestral realmente oferece espaço a cada uma. Confira também se existe uma base legível quando a melhoria não atua.
