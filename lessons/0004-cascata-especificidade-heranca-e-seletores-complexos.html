Cascata, especificidade,
herança e seletores complexos

Quando duas regras disputam a mesma propriedade, CSS não “se confunde”: ele executa um algoritmo. Hoje a turma aprende a prever o vencedor, reduzir seletores caros e usar a estrutura do HTML sem transformar cada correção numa guerra de !important.

O que uma regra @supports (display: grid) informa?

  • O navegador declara reconhecer esse par propriedade–valor.
  • O navegador é Chrome, Firefox ou Safari atual.
  • O layout não terá bugs nesse navegador.

1. A cascata é uma fila de decisões

A cascata escolhe um valor para cada propriedade de cada elemento. Ela não compara “regras inteiras” nem começa contando IDs. Primeiro elimina o que não se aplica; depois compara precedência; só então chega à especificidade.

OrdemPerguntaExemplo
1. RelevânciaA regra corresponde ao elemento e ao contexto?Uma regra de impressão sai da disputa na tela.
2. Origem, importância e camadaDe onde veio e em qual camada está?Normal, animação, !important, usuário.
3. EspecificidadeQual seletor tem maior peso?ID supera classe; classe supera tipo.
4. Proximidade de escopoEm @scope, qual raiz está mais perto?Só entra quando há empate anterior.
5. OrdemPersistiu o empate?A declaração posterior vence.

MDN — Introduction to the CSS cascade

Especificidade não governa tudo

Uma regra extremamente específica numa camada de menor precedência pode perder antes de a especificidade ser comparada. “Coloque mais IDs” não corrige uma decisão de origem, importância ou camada.

2. Especificidade: compare colunas, não some pontos

Para seletores comuns, registre três colunas: ID – classe – tipo. Compare da esquerda para a direita. Uma coluna maior decide; não existe conversão de dez classes em um ID.

SeletorIDClasse/atributo/pseudo-classeTipo/pseudo-elemento
article h2002
.card .titulo020
#app .titulo110
:where(.card) h2001

:where() e seus argumentos contribuem com especificidade zero. :is(), :not() e :has() não adicionam peso próprio, mas recebem o peso do argumento mais específico presente na lista.

:where(.card, .painel) h2 { margin-block: 0; } /* 0-0-1 */
:is(.card, #destaque) h2  { color: navy; }    /* 1-0-1 */

MDN — Specificity

A cor vermelha vence: .lista .card h2 tem especificidade 0–2–1. A última regra verde aparece depois, mas tem apenas 0–1–1. Ordem só resolve empate.

3. Pare de aumentar o seletor

O botão promocional deveria ser azul, mas uma correção acumulou ID e !important. Reorganize o CSS para que classes simples expressem base e variação. Não altere o HTML, não use ID no CSS e não use !important.

4. Herança não é cascata entre pai e filho

Depois que a cascata encontra o valor de uma propriedade em um elemento, a herança pode fornecer um valor ao descendente quando ele não recebeu valor especificado. Propriedades tipográficas como color e font-family normalmente herdam; propriedades de caixa como margin, padding e border normalmente não.

Use a herança

body {
  color: #292722;
  font-family: system-ui;
}

Descendentes recebem a base textual sem repetição.

Não suponha tudo herdado

.card { border: 1px solid; }
/* filhos não recebem essa borda */

Consulte a definição da propriedade quando houver dúvida.

Valor globalEfeito
inheritUsa explicitamente o valor calculado do pai.
initialUsa o valor inicial definido pela especificação.
unsetAge como inherit se a propriedade herda; caso contrário, como initial.
revertRecua para o valor da origem anterior na cascata.

Um seletor complexo não é melhor por ser longo. Ele deve expressar uma relação que o HTML garante. Se depender de cinco níveis acidentais de wrappers, uma mudança de marcação quebra o CSS mesmo quando o componente continua semanticamente igual.

MDN — Selectors and combinators

Sem adicionar classes ao HTML: (1) remova a margem apenas do parágrafo imediatamente após cada título; (2) destaque links externos pelo atributo href; (3) estilize somente listas diretamente filhas de nav. Evite afetar a lista aninhada dentro do item “Ajuda”.

6. Audite uma folha que “resolveu” a cascata

Pediram: “faça o CSS sempre aplicar o estilo certo”. O resultado funciona nesta marcação. Marque apenas os problemas reais; alguns seletores são precisos e deliberadamente leves.

  1. Os seletores dos títulos acumulam estrutura e especificidade desnecessárias.
  2. !important foi usado como estratégia normal de manutenção.
  3. A correção .menu a a procura links dentro de links.
  4. Usar :where(.card, .painel) h2 para manter baixa especificidade.
  5. Estilizar o botão por [aria-expanded="true"].
  6. Usar nav > ul para limitar a seleção à lista direta.

7. Aplique ao projeto integrador

Abra o esqueleto da home e crie a primeira folha do projeto. O objetivo ainda não é layout sofisticado; é estabelecer uma cascata sustentável:

  1. defina tipografia e cor herdáveis no body;
  2. estilize componentes com classes únicas e previsíveis;
  3. use combinador somente quando a relação fizer parte do contrato do HTML;
  4. não use ID para apresentação nem !important para ganhar disputa;
  5. no DevTools, explique uma declaração aplicada e uma riscada.
