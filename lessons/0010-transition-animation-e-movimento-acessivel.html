Aula 10 de 22 · 3h · CSS3 — transições, animações e acessibilidade

transition, animation
e movimento acessível

Movimento deve explicar mudança, não disputar atenção. Hoje a turma distingue transição de animação por keyframes, escolhe propriedades e tempos explícitos, mantém estados finais fora do efeito e oferece uma experiência coerente para quem pediu menos movimento.

Qual recurso é suficiente para suavizar a mudança de cor entre o estado normal e :hover?

  • transition
  • @keyframes infinito
  • setInterval()

1. Transição precisa de mudança de estado

Uma transição interpola valores quando o valor calculado de uma propriedade muda. Defina no estado-base quais propriedades participam, duração, curva e atraso. Algumas propriedades são discretas ou não animáveis; consulte o tipo de animação da propriedade.

.botao {
  background-color: #1d6373;
  transform: translateY(0);
  transition:
    background-color 160ms ease-out,
    transform 160ms ease-out;
}
.botao:hover { background-color: #154b57; }
.botao:active { transform: translateY(.125rem); }
Evite o contrato invisível

transition: all inclui futuras mudanças que o autor talvez nunca tenha decidido animar. Liste as propriedades para que manutenção não transforme tamanho, posição ou foco em movimento inesperado.

2. Curva e duração têm significado

DecisãoPergunta
DuraçãoA mudança é percebida sem atrasar a tarefa?
ease-outPrecisa chegar rapidamente e desacelerar no fim?
ease-inO elemento está saindo e pode acelerar?
linearVelocidade constante comunica progresso ou rotação?
AtrasoExiste razão funcional ou só espera adicionada?

Não existe duração universalmente acessível. Distância, escala, área ocupada, repetição e previsibilidade importam. Teste a tarefa, não apenas a suavidade.

3. Corrija a interação lenta e invasiva

O botão anima qualquer propriedade por dois segundos, cresce demais no hover e remove o foco. Restrinja a transição a cor de fundo e transform por 160ms, use deslocamento de -.125rem em hover e preserve um foco visível. Na preferência de movimento reduzido, remova transição e deslocamento.

4. Animação descreve uma linha do tempo

@keyframes define estados intermediários. A propriedade animation associa nome, duração, curva, atraso, quantidade de iterações, direção, fill mode e estado de execução. A duração inicial é 0s; declarar somente o nome não produz movimento visível.

@keyframes aparecer {
  from { opacity: 0; transform: translateY(.5rem); }
  to   { opacity: 1; transform: translateY(0); }
}
.mensagem { animation: aparecer 240ms ease-out both; }

animation-fill-mode controla valores antes ou depois do intervalo ativo; não use forwards para esconder o estado real do componente. O estilo-base deve continuar correto se a animação não executar.

ParteResponsabilidade
animation-nameEscolhe o conjunto de keyframes.
animation-durationDefine o tempo de um ciclo.
animation-iteration-countDefine quantas vezes; infinite nunca termina.
animation-directionControla execução normal, reversa ou alternada.
animation-play-statePermite pausar ou retomar.

5. Preferência reduzida é uma entrada do usuário

@media (prefers-reduced-motion: reduce) corresponde quando o usuário expressou preferência por menos movimento no sistema. Remova movimento não essencial ou substitua-o por uma mudança menos intensa. Não remova junto informação de estado, progresso ou confirmação.

.estado { opacity: 1; }
.estado.entrando { animation: aparecer 240ms ease-out; }

@media (prefers-reduced-motion: reduce) {
  .estado.entrando { animation: none; }
}

Uma regra global que reduz tudo para 0.01ms pode disparar eventos em ordem inesperada e destruir animações funcionalmente necessárias. Prefira decisões por componente e mantenha o estado final explícito.

Qual resposta é mais segura para uma decoração que pulsa sem parar?

  • Aumentar a velocidade para terminar antes
  • Parar o pulso em prefers-reduced-motion: reduce
  • Ocultar também o texto que ela acompanha

6. Movimento contínuo precisa de controle

Conteúdo que começa automaticamente, dura mais de cinco segundos e aparece junto de outro conteúdo precisa de mecanismo para pausar, parar ou ocultar, salvo quando o movimento é essencial. Uma preferência do sistema complementa; não substitui sempre o controle direto pedido pelo critério.

7. Audite intenção, duração e alternativa

A interface deve responder rápido, manter foco e respeitar preferências. Marque somente problemas reais; três escolhas são corretas.

  1. O cartão transiciona qualquer mudança por dois segundos.
  2. O hover amplia e gira excessivamente o cartão.
  3. O indicador pulsa indefinidamente sem alternativa reduzida.
  4. Salvar transiciona explicitamente a cor de fundo.
  5. Salvar mantém um outline visível.
  6. O ornamento flutua, mas respeita a preferência reduzida.

8. Reduza o pulso sem perder o status

O ponto de status cresce para o dobro quatro vezes por segundo. Reduza o máximo para 1.2, use ciclo de 900ms e pare a animação quando houver preferência por movimento reduzido. O texto deve permanecer.

9. Aplique ao projeto integrador

  1. liste cada movimento, seu objetivo, gatilho, duração e propriedade;
  2. substitua transition: all por contratos explícitos;
  3. teste hover, foco, ativação e estado final sem a animação;
  4. adicione tratamento por componente para movimento reduzido;
  5. forneça controle direto a movimento automático contínuo quando o critério exigir.
