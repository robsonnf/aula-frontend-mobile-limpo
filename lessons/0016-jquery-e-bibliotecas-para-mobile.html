jQuery e bibliotecas
para mobile

Uma biblioteca precisa justificar o que acrescenta ao projeto. Vamos reconstruir uma interação em jQuery, medir o custo da dependência e decidir quando a plataforma já resolve a tarefa. A F3 termina com comportamento verificável.

Ao final, você deverá ler e escrever seleções jQuery, delegar eventos, desmontar listeners com precisão e justificar uma escolha de biblioteca com evidências de versão, manutenção, peso, acessibilidade e compatibilidade.

Prévia, versão e DevTools

Os exemplos usam jQuery Core 4.0.0 completo, fixado e incluído em assets com licença MIT. Funcionam offline; não usam jQuery Mobile. Edite JS e aguarde a prévia reiniciar. 1. Carregamento: biblioteca antes de quem a utiliza

jQuery é uma biblioteca de JavaScript para operar o DOM e eventos, entre outras APIs; não é uma linguagem nem um requisito de Bootstrap 5.3. Em um projeto comum, carregue scripts clássicos externos com defer, na ordem biblioteca → aplicação. Scripts async não garantem essa ordem. $(function () { … }) aguarda o DOM estar pronto, mas não baixa uma biblioteca que está faltando.

<script defer src="../assets/jquery-4.0.0.min.js"></script>
<script defer src="../assets/app.js"></script>

O atelier insere a biblioteca local antes do JS do exercício. O build completo e o slim não oferecem exatamente as mesmas APIs; o slim exclui Ajax e efeitos, entre outros módulos conforme a versão. Consulte a distribuição que realmente foi carregada.

No DevTools — seção 1

Em Network, filtre jquery e recarregue a página: confira URL, status e tamanho. Em Sources, abra o arquivo para conferir o cabeçalho da versão. No Console do frame, avalie window.jQuery.fn.jquery. Bloqueie a URL local usando Request blocking, recarregue e observe o erro; depois desfaça o bloqueio.

2. Coleção jQuery, nó DOM e estado

$('#alvo') retorna uma coleção jQuery; $('#alvo')[0] acessa um nó DOM. Uma coleção vazia tem length zero. .text() escreve texto, .val() lê/escreve o valor de um campo e .prop() acessa propriedades como checked. .attr() trata atributos; para estados ARIA, escreva strings explícitas, como 'true' e 'false'.

Não use .html() com texto de formulário não confiável. Criar uma coleção jQuery não sanitiza dados por si só. A responsabilidade de preservar texto, foco e semântica continua sendo do autor.

No DevTools — seção 2

Em Elements, selecione o checkbox; no Console do frame compare window.jQuery('#aceite').prop('checked') com window.jQuery('#aceite').attr('checked') antes/depois da mudança. Em Accessibility observe checked. A propriedade atual e o atributo inicial não são a mesma coisa.

3. A mesma interação: nativo e jQuery

As duas implementações abaixo cumprem o mesmo contrato: um botão alterna a seleção e anuncia o estado. Compare requisitos, não apenas quantidade de caracteres. A versão nativa não precisa baixar jQuery; a versão jQuery pode fazer sentido num projeto que já utiliza a biblioteca e possui equipe preparada para mantê-la.

No DevTools — seção 3

Elements → Accessibility: compare nome, papel e pressed. Sources → breakpoint no handler: percorra cada implementação. Network mostra a dependência da página inteira, não atribui automaticamente bytes a cada botão. Para comparar sem jQuery, use páginas separadas com os mesmos requisitos.

4. Exercício: delegação e estado com jQuery

$lista.on('click.favoritos', 'button[data-favorito]', handler) delega o evento aos descendentes correspondentes. No handler com função tradicional, this é o elemento correspondente ao seletor; event.target pode ser seu span interno. Em jQuery, event.delegateTarget identifica o ancestral onde a delegação foi instalada. Não transporte automaticamente a semântica de currentTarget de um listener nativo para o wrapper jQuery.

Mantenha a criação de projetos. Corrija a seleção para os botões atuais e futuros, incluindo clique no span. Use uma delegação na lista, altere aria-pressed e informe o total de favoritos. A segunda ativação deve desmarcar.

Inspecione o ponto de instalação, o seletor delegado e o elemento que realmente recebeu a ação. Compare o estado lido com o estado escrito, incluindo o formato dos valores ARIA. Adicione um projeto antes de concluir.

No DevTools — seção 4

Em Sources pause no handler delegado; examine this, e.target e e.delegateTarget se declarar o parâmetro e. Elements → Accessibility deve mostrar o estado no botão, inclusive após clicar no span. Não basta alterar um atributo no filho visual.

5. Exercício: montar duas vezes sem duplicar a ação

Namespaces ajudam a remover somente os listeners de um componente. .off('click.contador') preserva click de outros namespaces; .off('click') é mais amplo. No jQuery, retornar false do handler chama preventDefault e stopPropagation; em addEventListener nativo, retornar false não tem esse efeito. Prefira intenções explícitas e verifique qual API está usando.

Repare montar(): depois de acioná-la várias vezes, cada clique em Contar deve acrescentar exatamente um ao contador principal. Preserve o listener click.telemetria, que atualiza seu contador independentemente. Use um namespace próprio para a funcionalidade.

Monte três vezes e conte uma. Observe quantas execuções ocorrem. Investigue como remover um conjunto de listeners sem apagar o trabalho de outro componente.

No DevTools — seção 5

Em Sources, coloque um breakpoint na atualização de total e conte as pausas para um clique. O painel Event Listeners pode mostrar um dispatcher jQuery para vários handlers: esse número sozinho não demonstra ausência de duplicação. Confira também a observação local, que deve continuar aumentando uma vez.

6. jQuery Mobile: reconhecer legado e planejar migração

jQuery Core e jQuery Mobile são projetos distintos. O anúncio oficial de 07/10/2021 descontinuou jQuery Mobile; não o adote como base de um projeto novo. Uma página antiga pode continuar abrindo, mas isso não demonstra manutenção, compatibilidade futura nem adequação de acessibilidade.

Ao encontrar uma aplicação antiga: inventarie versões e plug-ins; registre os fluxos de navegação e formulários; substitua um componente por vez; teste teclado, toque, foco e histórico. Não remova a dependência antes de mapear quem a usa. Um upgrade de jQuery Core também exige testar as APIs e os plug-ins da aplicação.

Para revelar conteúdo simples, details/summary pode cumprir o requisito sem biblioteca. Essa demonstração não é um substituto universal para todos os componentes do jQuery Mobile; uma migração depende dos contratos da aplicação real.

No DevTools — seção 6

Elements: observe o atributo open mudar no details. Accessibility: confira o controle e o estado expandido. Network: esta prévia não carrega jQuery; outros iframes da mesma aula carregam. Filtre por frame/Initiator para não misturar medições.

7. Bibliotecas para mobile: decidir por requisitos

PerguntaEvidência a recolher
A plataforma já atende?Protótipo com details, controles nativos ou scroll snap
Qual dependência?Versão fixa, distribuição, licença e plug-ins necessários
Quem mantém?Repositório oficial, releases, avisos e documentação de migração
Qual custo real?Transferência, tamanho do recurso e trabalho observado em Performance
Como se opera?Teclado, toque, leitor de tela, foco, movimento reduzido e zoom
Como sai do projeto?Desmontagem documentada e impacto da remoção

Exemplo de decisão: Bootstrap 5.3 já está no projeto F2 e oferece componentes; jQuery acrescenta uma API de DOM/eventos; CSS scroll snap pode atender uma galeria simples. Essas opções não são equivalentes para todos os requisitos. Não instale uma biblioteca só porque contém “mobile” no nome.

A galeria não tem autoplay e usa deslocamento instantâneo, sem exigir tratamento especial para reduzir animação. A rolagem manual permanece disponível sem JS. Se adicionar transição suave, consulte prefers-reduced-motion e teste os dois modos. Uma biblioteca de galeria mais complexa só se justifica por requisitos adicionais.

No DevTools — seção 7

Elements → Styles: localize overflow e scroll-snap-type. Em Rendering, emule prefers-reduced-motion e confirme operação. Network → Disable cache + recarregar permite medir carga fria; registre separadamente transferred e resource size. Em Performance grave a interação; bytes menores não garantem execução mais rápida.

8. Auditoria: eventos e CSS de um componente mobile

Requisitos: cada ativação do botão Ação conta exatamente uma vez, inclusive por teclado; repetir Montar não multiplica handlers e não remove o observador local. CSS deve manter foco e permitir gestos nativos. Audite JS e CSS; repare o JS onde houver descumprimento.

Teste montagem repetida, toque e teclado separadamente. Inspecione se a remoção atinge somente o componente. Para cada objeção de CSS, compare o estilo calculado com o requisito antes de classificá-la.

  1. touch-action:auto impede qualquer botão de responder ao toque.
  2. Registrar a mesma ação em touchstart e click pode duplicar a contagem.
  3. As duas montagens iniciais acumulam handlers.
  4. flex-wrap e gap são incompatíveis em interfaces mobile.
  5. O status deveria usar .html() para atualizar seu texto.
  6. Montar apaga o listener click.observador.
  7. O outline de foco muda obrigatoriamente o tamanho de layout do botão.
  8. Falta jQuery Mobile para Core conseguir tratar click nos botões.
No DevTools — seção 8

Sources → breakpoint na contagem: compare execuções antes/depois de Montar. Em Elements → Computed examine touch-action, flex-wrap, gap e outline ao focar. Emule toque e repita por teclado. Os contadores são observáveis; não dependa de inspecionar estruturas internas privadas de jQuery.

Por que usar namespace ao desmontar uma funcionalidade?

  • Para garantir que qualquer plug-in antigo funcione
  • Para remover seus handlers sem atingir os demais
  • Para transformar todo click em touchstart

9. Entrega da F3: a mesma tarefa, duas implementações

  1. Finalize na home a interação nativa da A15 e preserve sua versão.
  2. Implemente uma peça equivalente em jQuery numa página separada; não execute as duas no mesmo botão.
  3. Teste mesmos dados, item dinâmico, teclado, toque, zoom e remontagem.
  4. Compare carga fria e comportamento no mesmo navegador, dispositivo e condições de rede.
  5. Em COMPATIBILIDADE.md, registre versões, licença, medidas e a decisão de manter ou remover a dependência.

Use os critérios da seção 7 para avaliar uma biblioteca candidata do seu projeto. Se a plataforma já cumprir tudo, essa também é uma decisão justificável. A entrega inclui home operável, comparação e limites conhecidos, preparando a auditoria da A17.

No DevTools — seção 9

Network compara as duas páginas com cache desativado. Performance registra a mesma tarefa. Accessibility confirma nomes/estados; Sources confirma uma execução por ação. Anote o contexto dos resultados: medidas do laboratório não são dados de todos os usuários.
