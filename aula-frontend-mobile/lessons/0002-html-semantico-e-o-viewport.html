HTML semântico
e o viewport

Antes de fazer caber, precisamos dizer o que cada parte é. Hoje a turma transforma uma pilha de divs em um documento navegável e vê uma única linha no <head> mudar a escala inteira da página no celular.

Roteiro — retomada (15 min)

Entregar as quatro perguntas em papel, sem consulta: (1) qual folha todo dispositivo aplica? (2) o que uma media query min-width faz? (3) por que breakpoint não tem nome de aparelho? (4) apagar todas as media queries quebra o celular?

Corrigir em pares por 3 min e só então abrir a discussão. Interleaving ainda não existe na A2; a partir da A5, misturar uma pergunta de 3–4 encontros atrás.

Na folha mobile-first da A1, qual CSS chega a todo dispositivo?

  • A folha base, fora das media queries.
  • A regra dentro do maior min-width.
  • A regra com o nome do celular no comentário.

1. HTML não descreve aparência

HTML descreve a estrutura e o significado do conteúdo. CSS decide como esse conteúdo aparece. JavaScript decide o que ele faz quando algo acontece.

Parece um título

<div class="titulo-grande">
  Serviços
</div>

O navegador vê um contêiner genérico. A aparência depende do CSS.

É um título

<h2>Serviços</h2>

O navegador, o leitor de tela e o mecanismo de busca recebem a mesma estrutura.

Semântica não significa “usar tags diferentes para evitar div”. Significa escolher o elemento cujo papel corresponde ao conteúdo. Quando nenhum elemento tem esse papel, div e span continuam corretos.

Roteiro — exposição 1 (40 min)

No DevTools, desligar o CSS dos dois exemplos. O primeiro perde o título; o segundo conserva a hierarquia. Depois abrir a árvore de acessibilidade: a diferença deixa de ser opinião visual.

Não vender semântica como SEO mágico. O ganho imediato é uma estrutura que agentes diferentes conseguem interpretar. SEO entra formalmente na A18.

2. A árvore antes das folhas

Uma página não é uma coleção de caixas. É um documento com regiões e uma hierarquia de títulos. Estes elementos resolvem grande parte de uma home:

ElementoPergunta que respondeArmadilha comum
headerQual é a introdução desta página ou seção?Não é sinônimo de faixa no topo.
navEste bloco contém navegação importante?Nem todo grupo de links precisa de uma região nav.
mainQual é o conteúdo principal único desta página?Deve haver apenas um main visível.
sectionEste agrupamento tem tema e título próprios?Não é uma div com nome sofisticado.
articleIsto faz sentido distribuído sozinho?Nem todo cartão é um artigo.
footerQuais informações fecham esta página ou seção?Pode existir dentro de um article.
Teste da section

Se você não consegue dar um título útil ao bloco, provavelmente ele não é uma section. Use div para agrupamento puramente visual.

MDN — HTML elements reference

Experimente: expanda a prévia e navegue apenas com Tab. Os links continuam sendo links, o salto chega ao conteúdo e os títulos continuam organizando o documento. Nenhuma dessas propriedades veio do CSS.

3. Marque o significado, não o desenho

Reescreva somente o HTML. Preserve todo o texto e os links, mas substitua as caixas genéricas pelos elementos que representam cabeçalho, navegação, conteúdo principal, seção, artigo e rodapé. Crie uma hierarquia de títulos que não pule nível.

Roteiro — prática 1 (30 min)

10 min individual, 5 min em dupla comparando escolhas, 10 min projetando duas soluções diferentes, 5 min de síntese. Aceitar article ou div para os pratos se a justificativa for coerente; o objetivo é decidir, não adivinhar a tag que o professor imaginou.

Intervalo de 15 min ao final. Deixar na tela: “na volta, uma linha muda a página inteira sem tocar no CSS”.

4. O celular não começa com 390 pixels

O navegador móvel precisa encaixar páginas antigas que foram desenhadas para telas largas. Sem instrução, ele pode usar um viewport de layout virtual mais largo e reduzir a página inteira para caber. O site parece uma miniatura.

<meta name="viewport"
      content="width=device-width, initial-scale=1">

width=device-width faz a largura do viewport de CSS acompanhar a largura do dispositivo. initial-scale=1 define a escala inicial em 1:1. Essa linha não torna o site responsivo; ela permite que o CSS responsivo trabalhe na largura que você acredita estar testando.

MDN — Viewport meta tag

Não bloqueie o zoom

Não use user-scalable=no nem maximum-scale=1. Pessoas com baixa visão precisam ampliar o conteúdo; navegadores podem ignorar o bloqueio, mas isso não transforma uma instrução hostil em boa prática.

Controle tirado do usuário

<meta name="viewport"
 content="width=device-width,
 initial-scale=1,
 maximum-scale=1,
 user-scalable=no">

Escala inicial, zoom preservado

<meta name="viewport"
 content="width=device-width,
 initial-scale=1">
Roteiro — exposição 2 (35 min)

A demonstração fiel exige celular real. Abrir duas páginas idênticas, uma com a meta e outra sem, servidas por npm start no IP da rede. Pedir que a turma diga a largura mostrada no DevTools com document.documentElement.clientWidth.

Separar três conceitos no quadro: pixel físico, pixel CSS e densidade. Não entrar em cálculo de devicePixelRatio; basta impedir a frase “meu celular tem 390 pixels”. Ele tem um viewport de 390 pixels CSS naquele estado.

O que a meta viewport faz sozinha?

  • Transforma qualquer layout fixo em responsivo.
  • Define a largura do viewport de CSS e a escala inicial.
  • Reduz o tamanho de todas as imagens para a tela.

5. Audite uma resposta plausível

Pediram a uma IA: “configure meu HTML para celular e SEO”. O resultado abre e parece normal. Marque apenas o que é problema. Há decisões corretas na lista.

  1. A configuração tenta impedir o zoom do usuário.
  2. O nome da clínica parece título, mas continua sendo uma div genérica.
  3. A página declara charset="utf-8".
  4. O documento usa lang="pt-BR".
  5. Existe um title descritivo no head.
Roteiro — auditoria (15 min dentro da prática 2)

Exigir fonte para o primeiro achado. O objetivo é distinguir “eu não gosto” de “há consequência documentada”. Os três decoys medem se o aluno sabe preservar o que já está certo.

6. Aplique ao projeto integrador

As cinco seções trazidas da A1 agora viram uma árvore HTML. Ainda sem layout e sem cores. O arquivo desta fase precisa conter:

  1. <!doctype html>, lang="pt-BR", UTF-8, título útil e a meta viewport correta;
  2. um único main visível e um h1 que nomeie a página;
  3. regiões escolhidas pelo papel do conteúdo, não pelo desenho desejado;
  4. hierarquia de títulos sem saltos usados apenas para mudar o tamanho;
  5. links reais quando a ação é navegar; botões ficam para ações, na A15.
Entrega de hoje — esqueleto da home

Crie index.html com conteúdo real nas cinco seções. Abra sem CSS e leia de cima a baixo. Se a ordem fizer sentido e os títulos contarem a história da página, o esqueleto está de pé. Traga o arquivo para a A3.

Roteiro — prática 2 / projeto (40 min)

Primeiros 25 min: cada aluno marca a própria home. Próximos 10: troca com colega, que navega pelos títulos e escreve uma dúvida de estrutura. Últimos 5: commit/export do arquivo e registro do que ficou pendente.

Circular procurando duas confusões: section usada para qualquer caixa e nível de título escolhido pelo tamanho visual. Não corrigir tomando o teclado; perguntar “qual é o tema desta seção?” e “de quem este título é filho?”.

Roteiro — fechamento (5 min)

Pedir duas frases em voz alta: “HTML diz…” — significado; “viewport diz…” — qual largura CSS e escala inicial usar. Anunciar a A3: manter esse documento útil quando capacidades, rede ou navegador não forem iguais.

Leitura primária

Leia MDN — Document and website structure e consulte MDN — Viewport meta tag. Na primeira, observe como regiões e títulos formam o documento; na segunda, procure o alerta sobre zoom. As duas decisões reaparecem em acessibilidade, SEO e testes.

Ficou alguma coisa mal explicada? Pergunte agora. Uma árvore errada recebe CSS na A4 e fica mais cara de corrigir; uma árvore clara aguenta todas as próximas camadas.
