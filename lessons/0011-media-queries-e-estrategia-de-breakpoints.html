Media queries
e estratégia de breakpoints

Breakpoint não é nome de aparelho: é o ponto em que o conteúdo pede outro arranjo. Hoje a turma parte de uma base fluida pequena, acrescenta mudanças com condições de largura e consulta também capacidades, preferências e mídia de impressão.

Qual evidência justifica melhor um breakpoint?

  • “768px é tablet”
  • A navegação deixa de caber sem sobreposição
  • O framework possui uma variável com esse número

1. A consulta pergunta sobre o ambiente

Uma media query combina um tipo de mídia opcional, expressões de features e operadores lógicos. Ela resulta em verdadeiro ou falso; quando verdadeira, suas regras participam normalmente da cascata.

@media print { … }
@media (min-width: 48rem) { … }
@media (hover: hover) and (pointer: fine) { … }
@media (prefers-reduced-motion: reduce) { … }
ParteExemplosPergunta
Tipoall, screen, printQual meio apresenta o documento?
Faixawidth, height, resolutionO valor está em qual intervalo?
Discretahover, pointer, orientationQual capacidade ou estado corresponde?
Preferênciaprefers-reduced-motion, prefers-color-schemeO que o usuário comunicou?

Sem tipo explícito, a consulta vale para all. Uma folha ligada com media ainda pode ser baixada quando a consulta não corresponde: a condição controla aplicação, não garante economia de rede.

2. width consulta viewport, não modelo de aparelho

A feature width representa a largura do viewport — ou a caixa da página em mídia paginada. Prefira-a a device-width, que descreve a superfície do dispositivo e não o espaço atualmente disponível ao documento.

A meta viewport estudada na A2 permite uma largura coerente em navegadores móveis. Ela não corrige conteúdo rígido: layout fluido continua sendo a base.

3. Converta desktop-first em melhoria progressiva

A página nasce em duas colunas e tenta desfazer o layout abaixo de 768px. Faça a base ter uma coluna e, a partir de 48rem, crie sidebar de 14rem mais conteúdo flexível. Preserve gap: 1rem.

4. Breakpoint vem do conteúdo

  1. comece na menor largura útil e deixe o conteúdo fluir;
  2. aumente o viewport até surgir uma oportunidade real de composição;
  3. marque o primeiro ponto em que a mudança melhora leitura ou operação;
  4. teste imediatamente antes, no ponto e depois dele;
  5. repita com zoom, fonte maior, tradução e conteúdo extremo.

Catálogo de aparelhos

/* tablet */
@media (width: 768px) { … }

Corresponde somente à largura exata.

Evidência de conteúdo

/* menu e busca passam a caber lado a lado */
@media (min-width: 46rem) { … }

O comentário documenta o motivo observável.

5. Faixas precisam de fronteiras explícitas

min-width e max-width são inclusivos. Se duas consultas tocam em 40rem, ambas correspondem nesse ponto e a cascata decide. A sintaxe de comparação deixa inclusão ou exclusão visível.

@media (width < 40rem) { … }
@media (40rem <= width < 64rem) { … }
@media (width >= 64rem) { … }

Prefira camadas cumulativas com min-width quando o design cresce por melhorias. Use faixas somente quando um comportamento pertence de fato a um intervalo.

O que ocorre exatamente em 40rem?

  • @media (max-width: 40rem) deixa de corresponder
  • Ela e @media (min-width: 40rem) correspondem
  • Nenhuma consulta corresponde

6. Capacidade não é formato físico

orientation: landscape só informa que a largura do viewport é maior que a altura. Não significa desktop, mouse ou teclado. hover e pointer descrevem o apontador primário; as variantes any-* consideram qualquer apontador disponível.

.acao { min-block-size: 2.75rem; }
@media (hover: hover) and (pointer: fine) {
  .acao:hover { text-decoration-thickness: .18em; }
}

A base continua operável por toque e teclado. A consulta acrescenta uma melhoria; não esconde a única rota para conteúdo ou ação.

7. Audite hipóteses, fronteiras e modalidades

A página deve funcionar em qualquer janela, com toque, teclado, mouse, impressão e movimento reduzido. Marque somente problemas reais.

  1. Landscape é usado como sinônimo de desktop.
  2. A ajuda essencial existe apenas em hover.
  3. ARIA é usado para justificar conteúdo oculto.
  4. O menu usa wrapping sem breakpoint.
  5. Os cartões ganham duas colunas em 48rem.
  6. Existem consultas de impressão e movimento reduzido.

8. Elimine sobreposição entre faixas

As consultas se sobrepõem nas fronteiras. Mantenha uma base de uma coluna, passe a duas em 40rem e a três em 64rem usando melhorias cumulativas.

9. Aplique ao projeto integrador

  1. troque rótulos de aparelhos pelo motivo de cada breakpoint;
  2. mantenha a base utilizável antes de qualquer consulta;
  3. teste antes, no ponto e depois de cada fronteira;
  4. use hover/pointer somente para melhorias;
  5. confira impressão, movimento reduzido, zoom, fonte e conteúdo extremos.
